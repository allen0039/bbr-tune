# 远程服务器 TCP / BBR 均衡寻优工具

`bbr-tune.sh` 是运行在 **远程 Linux 服务器** 上的交互式 TCP/BBR 测试与参数寻优工具。当前版本为 `2.2.0`。

工具面向专用网络代理、跨境转发和长时延大带宽链路。它以真实的“服务器下载到本地”测试结果为依据，在服务器端持续扩大 TCP 缓存；检测到性能边界后自动回退精调，并同时约束单连接与多连接性能。

## 一、作用范围

脚本只调整远程服务器上的核心网络参数：

- `net.ipv4.tcp_congestion_control = bbr`
- `net.core.default_qdisc = fq`
- `net.core.rmem_max` / `net.core.wmem_max`
- `net.ipv4.tcp_rmem` / `net.ipv4.tcp_wmem`
- `net.ipv4.tcp_mem`
- `tcp_moderate_rcvbuf`、SACK、DSACK、TCP 窗口缩放

本地电脑只需执行脚本显示的 `iperf3` 客户端命令。脚本不会修改本地电脑的 TCP 参数、路由、队列规则、防火墙或软件包。

## 二、目标带宽的定义

测试方向固定为：

```text
远程服务器 ───── 下载流量 ─────> 本地电脑
```

`目标带宽 Mbps` 表示这条端到端下载链路期望达到的上限，建议填写以下限制中的较小值：

```text
min(
  云服务器或宿主机出站带宽上限,
  服务器物理端口上限,
  本地下载带宽上限,
  已知的中间链路上限
)
```

示例：

- 服务器出站限制为 `200 Mbps`，本地下载上限为 `1000 Mbps`：填写 `200`。
- 服务器端口为 `1000 Mbps`，本地下载上限为 `500 Mbps`：填写 `500`。
- 两端均为千兆，但跨境路径长期只能达到约 `300 Mbps`：可填写 `300`。

该数值仅用于 BDP、达标门槛和评分计算，不会在任一端实施限速。

## 三、单连接与多连接联合评估

每组候选参数均执行两次反向测试：

1. **单连接测试**：固定使用 `-P 1`，评价单条代理连接的吞吐与重传。
2. **多连接测试**：默认使用 `-P 8`，评价并发代理业务的聚合吞吐与稳定性。

单连接和多连接的质量分等权进入调和均值模型。调和均值会显著惩罚“多连接很快、单连接明显变慢”或相反的偏科配置。

候选参数还必须满足独立基线保护条件：

```text
候选单连接吞吐 ≥ 调优前单连接吞吐 × 95%
候选多连接吞吐 ≥ 调优前多连接吞吐 × 95%
```

任一场景低于保护线，该候选均不会被选为最优参数。最终候选还会重新执行一组单连接和多连接测试；复核失败时自动恢复调优前配置。

## 四、基于总内存的 TCP 缓存策略

服务器用于专用网络代理时，工具允许 TCP 聚合内存使用更积极的预算：

```text
有效总内存 = min(物理总内存, cgroup 总内存上限)
TCP 聚合内存预算 = 有效总内存 × 2 / 3
```

`MemAvailable` 只记录在日志中用于运行状态分析，不参与预算计算。

系统级 `tcp_mem` 阈值按下列比例设置：

```text
low      = 有效总内存 × 1 / 3
pressure = 有效总内存 × 1 / 2
high     = 有效总内存 × 2 / 3
```

单 socket 的接收和发送缓存上限用于候选搜索：

```text
单 socket 搜索上限 = min(TCP 聚合内存预算, 2047 MiB)
```

`2047 MiB` 用于规避常见 Linux 内核中字节型 sysctl 的有符号 32 位整数上限。系统级聚合预算仍可高于该数值。

| 有效总内存 | TCP 聚合预算 | 单 socket 搜索上限 |
|---:|---:|---:|
| 256 MiB | 170 MiB | 170 MiB |
| 1 GiB | 682 MiB | 682 MiB |
| 2 GiB | 1365 MiB | 1365 MiB |
| 4 GiB | 2730 MiB | 2047 MiB |
| 8 GiB | 5461 MiB | 2047 MiB |
| 16 GiB | 10922 MiB | 2047 MiB |

这些值是内核 TCP 自动内存管理可使用的上限，并不表示脚本启动后会立即分配对应数量的物理内存。`2/3` 策略适用于专用网络代理服务器；如果服务器还承载数据库、编译或其他高内存业务，应先评估整体内存余量。

## 五、自动寻优流程

1. 检查服务器依赖；服务器缺少 `iperf3` 时自动安装。
2. 在 `20000～59999` 范围选择一个当前未被占用的随机 TCP 端口。
3. 保存调优前的 sysctl、qdisc、持久化文件和系统状态。
4. 分别执行调优前单连接与多连接基线测试。
5. 从 iperf3 JSON 或服务器 TCP socket 自动取得端到端 RTT；必要时使用 ICMP ping 作为备用来源。
6. 根据目标带宽与 RTT 计算 BDP，并结合服务器有效总内存生成缓存候选。
7. 从接近一个 BDP 的缓存值开始倍增探索，直至发现综合性能回落或到达技术上限。
8. 发现性能边界后，在最后一个安全点与越界点之间二分精调到 `1 MiB` 粒度。
9. 在满足单连接、多连接保护条件的候选中选择均衡评分最高的配置。
10. 对最优候选再次执行单连接与多连接复核。
11. 复核通过后保留运行时参数，并按用户选择写入开机配置；复核失败则恢复原配置。
12. 生成专业评估报告，保存逐轮结果、原始 JSON 和系统状态供跨时段比较。

候选数量不设人工上限，实际轮数由 BDP、内存上限、性能边界及回退区间共同决定。由于每组配置都需要单连接和多连接两次测试，完整测试次数约为候选轮数的两倍，另加基线与最终复核。

## 六、安装与运行

在远程服务器执行：

```bash
git clone https://github.com/dingding229/bbr-tune.git
cd bbr-tune
chmod +x bbr-tune.sh
sudo ./bbr-tune.sh
```

交互菜单：

```text
╔══════════════════════════════════════════════════════════════╗
║        远程服务器 TCP / BBR 自动寻优工具 v2.2.0             ║
╚══════════════════════════════════════════════════════════════╝

  1) 自动测试并选择最优 TCP 参数
  2) 查看当前 TCP / BBR 状态
  3) 查看历史测试与对比记录
  4) 确认保留当前参数
  5) 恢复调优前参数
  6) 使用说明
  0) 退出
```

命令行方式：

```bash
sudo ./bbr-tune.sh autotune \
  --bandwidth-mbps 1000 \
  --server-address <服务器公网IP或域名> \
  --parallel 8 \
  --duration 15 \
  --target-utilization 90 \
  --max-retrans-percent 1
```

参数说明：

- `--parallel`：多连接评估使用的并发连接数，默认 `8`；单连接测试始终使用 `1`。
- `--duration`：每次单项测试的持续时间，默认 `15` 秒。
- `--target-utilization`：绝对吞吐达标门槛，默认目标带宽的 `90%`。
- `--max-retrans-percent`：允许的最大估算重传率，默认 `1%`。
- `--persist`：最终复核通过后写入开机配置。
- `--force`：允许覆盖无法完整自动重建的自定义 root qdisc，仅建议在审计现有队列后使用。

固定安全默认值：

```text
每次测试等待本地连接：300 秒
安全自动回滚窗口：3600 秒
```

这两项不在交互界面中询问。开始新一轮调优时，如果上一轮仍处于待确认状态，脚本会取消旧回滚计时器，并以服务器当前参数作为新基线。

## 七、本地测试操作

服务器每次启动 iperf3 后会显示本地命令。例如单连接测试：

```bash
iperf3 -c <服务器IP> -p 43817 -R -P 1 -t 15 -i 1
```

同一候选的多连接测试会随后显示：

```bash
iperf3 -c <服务器IP> -p 43817 -R -P 8 -t 15 -i 1
```

本地只需要按服务器提示依次执行命令。服务器每 5 秒显示等待或运行状态；测试完成后输出区间吞吐、Retr、平均吞吐、估算重传率、RTT 和达标状态。

## 八、评分与最优值判定

单项基础指标：

```text
最低达标吞吐 = 目标带宽 × target-utilization
估算重传率 = Retr × 1448 / 发送字节数 × 100%
```

联合评价原则：

1. 分别计算单连接与多连接的目标完成度，并对超限重传进行扣分。
2. 使用两项质量分的调和均值作为综合评分，避免单侧高性能掩盖另一侧退化。
3. 单连接和多连接吞吐均不得低于对应基线的 `95%`。
4. 综合评分显著下降或任一基线保护条件失效时，判定已触及性能边界。
5. 越界后回退并二分精调，持续逼近性能边界内的最优值。
6. 最优候选必须通过独立复核；保护条件失效或综合评分低于基线时恢复原配置。

网络性能受时段、路由、运营商策略和客户端接收能力影响。报告中的“最优”表示当前客户端、当前路径和本次测试时段下的实测均衡最优值，建议在业务低峰与高峰分别测试，并结合历史记录评估稳定性。

## 九、日志与专业评估报告

每次运行创建独立会话目录：

```text
/var/lib/bbr-tcp-tuning/sessions/<时间戳-PID>/
```

主要文件：

```text
run.log                 完整屏幕输出和运行日志
results.tsv             每个场景的参数、RTT、吞吐、重传、单项分和综合分
comparison.txt          TCP/BBR 参数优化评估报告
system-before.txt       调优前 sysctl、qdisc 和 TCP 计数器
system-after.txt        调优后 sysctl、qdisc 和 TCP 计数器
before-*.json           调优前 iperf3 原始数据
candidate-*.json        候选参数 iperf3 原始数据
final-*.json            最优参数复核原始数据
*.rtt-samples           测试期间采集的 TCP RTT
*.err                   对应测试的标准错误输出
```

`comparison.txt` 包含：

- 执行结论与配置处置结果；
- 联合评价方法和基线保护条件；
- 测试环境、目标带宽、RTT 与搜索轮数；
- 总内存、聚合 TCP 内存预算、单 socket 上限和 `tcp_mem` 阈值；
- 单连接和多连接调优前后吞吐、重传率及综合评分；
- sysctl 与 qdisc 的调优前后参数；
- 性能边界、最优候选和逐轮测试明细；
- 完整审计文件路径。

跨时段汇总保存在：

```text
/var/lib/bbr-tcp-tuning/history.tsv
```

查看格式化历史：

```bash
./bbr-tune.sh history
```

历史表同时记录单连接与多连接的前后吞吐、变化率、重传率、综合评分、缓存值和处置结果。字段升级时，旧格式文件会以 `history.legacy-<时间>.tsv` 保留。

## 十、持久化、确认与回滚

默认只在当前运行时应用最优参数。使用 `--persist` 后，最终复核通过时写入：

```text
/etc/sysctl.d/99-bbr-tcp-tuning.conf
/etc/modules-load.d/bbr-tcp-tuning.conf
/etc/default/bbr-tcp-tuning
/usr/local/sbin/bbr-tcp-qdisc
/etc/systemd/system/bbr-tcp-tuning.service
```

调优完成后，请通过独立 SSH 会话确认服务器网络正常，并在 3600 秒内执行：

```bash
sudo ./bbr-tune.sh confirm
```

立即恢复调优前参数：

```bash
sudo ./bbr-tune.sh rollback --yes
```

脚本异常退出、测试超时或收到中断信号时，会立即尝试恢复调优前参数；独立安全计时器提供第二层保护。

## 十一、安全说明

1. 脚本必须在远程 Linux 服务器运行。
2. 脚本只修改服务器端 TCP/BBR 参数。
3. 测试端口从 `20000～59999` 随机选择，并在启动前检查监听占用。
4. 脚本不会修改云安全组或服务器防火墙；请临时允许屏幕显示的 TCP 端口。
5. 检测到自定义 root qdisc 时默认拒绝覆盖；使用 `--force` 前应确认现有 QoS 可以被替换。
6. 自定义 qdisc 的 class 和 filter 无法通用重建，应在强制运行前自行备份。
7. 在执行 `confirm` 前不要移动或删除脚本，以免安全回滚任务无法找到脚本。
8. 单连接策略限制、物理线路上限、本地接收性能和运营商 QoS 无法仅通过服务器 TCP 参数消除。
9. `2/3` TCP 聚合内存预算属于专用代理服务器的积极配置，不建议直接用于混合负载主机。
